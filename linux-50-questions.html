Basic Filesystem & Navigation Q 01–15
01 Your team deployed a new app to /opt/myapp. How do you quickly see all files including hidden configs, file sizes in human-readable format, and sort them by modification time? ls ▾

ls lists directory contents. By itself it's basic — but combining flags makes it a powerful audit tool.

bash
$ ls -lahtr /opt/myapp total 64K drwxr-xr-x 3 root root 4.0K Jun 10 09:00 ../ -rw-r--r-- 1 app app 312 Jun 10 09:01 .env # hidden config -rw-r--r-- 1 app app 1.2K Jun 15 14:22 config.yaml drwxr-xr-x 4 app app 4.0K Jun 18 10:47 logs/ -rwxr-xr-x 1 app app 28K Jun 19 08:31 server # newest first (with -r) drwxr-xr-x 5 app app 4.0K Jun 19 08:31 ./

Flag breakdown: -l long format (permissions, owner, size), -a show hidden files (dotfiles like .env), -h human-readable sizes (K/M/G), -t sort by modification time, -r reverse so newest appears at the bottom (easiest to see in a terminal).

💡

In DevOps: use ls -laht | head -20 after a deploy to instantly see what changed. Pair with stat filename to get nanosecond-precision timestamps for deployment audits.

02 You're SSH'd into a production server. How do you find out exactly where you are in the filesystem, and navigate to the app's log directory three levels deep without typing the full path repeatedly? pwd · cd ▾

pwd (print working directory) and cd (change directory) are navigation basics, but knowing the shortcuts saves minutes on live incidents.

bash
$ pwd /home/ubuntu $ cd /var/log/nginx/access # absolute path $ cd ../../ # go up 2 levels → /var/log $ cd - # jump back to previous dir $ cd ~ # go home always $ pushd /etc/nginx # save current dir onto stack $ popd # return to saved dir
💡

cd - is a lifesaver during incidents — it toggles between your last two directories. pushd/popd lets you maintain a directory stack while jumping around multiple config locations.

03 A config file has 2,000 lines. How do you read it without opening an editor, and navigate it efficiently? When does cat get you in trouble on production? cat · less ▾

cat dumps a file to stdout instantly. less is a pager — it loads the file lazily, essential for large files or log inspection.

bash
$ cat /etc/nginx/nginx.conf # fine for small files $ less +G /var/log/app.log # open at end (like tail) $ less -N config.yaml # show line numbers # Inside less: /pattern → search forward n → next match G → go to end g → go to beginning q → quit # ⚠️ This can crash a terminal or flood a shared session: $ cat /var/log/access.log # 8GB file → disaster
⚠️

Never cat a binary file or a file larger than a few MB in a shared terminal session. It can flood stdout with garbage characters that break your terminal — use file myfile first to check the type, then less.

04 In your CI pipeline script, you need to create a nested directory structure /deploy/v1.2.3/configs/ in one command, and later clean up an empty artifacts folder. How? mkdir · rmdir ▾

mkdir creates directories. The -p flag is critical in scripts — it creates parent directories and doesn't fail if the directory already exists.

bash
$ mkdir -p /deploy/v1.2.3/configs # create full tree, safe to re-run $ mkdir -p build/{assets,logs,tmp} # brace expansion — create 3 dirs $ rmdir artifacts/ # only works if empty $ rmdir -p a/b/c/ # remove c, then b, then a if all empty
💡

Brace expansion mkdir -p src/{components,hooks,utils} is extremely useful in pipeline bootstrapping. Always use -p in scripts to make them idempotent (safe to re-run).

05 Before a risky deployment, you want to back up /etc/nginx/ entirely. After the deploy fails, you need to restore it. How do you copy directories recursively and move files atomically? cp · mv ▾

cp copies files/directories. mv moves or renames — crucially, on the same filesystem it's an atomic rename (instant, no data copy).

bash
# Backup before deploy $ cp -a /etc/nginx /etc/nginx.bak.$(date +%Y%m%d) # -a = archive mode: recursive + preserve permissions/timestamps/symlinks # Restore atomically (zero-downtime swap) $ mv /etc/nginx /etc/nginx.broken $ mv /etc/nginx.bak.20240619 /etc/nginx # Copy only newer files (incremental) $ cp -u src/* dest/
💡

The mv atomic rename trick is used in zero-downtime deploys: write to app.new, then mv app.new app — readers always see a complete file, never a partial write. On different filesystems, mv becomes a copy+delete and loses atomicity.

06 A cleanup script needs to delete all .tmp files older than 7 days in /tmp. How do you do it safely without accidentally removing the wrong files? rm · find ▾

rm is permanent — no trash, no undo. The safe pattern for bulk deletes: always dry-run with find first, then pipe to delete.

bash
# Step 1: dry-run — see what WOULD be deleted $ find /tmp -name "*.tmp" -mtime +7 -type f /tmp/build_cache_abc.tmp /tmp/session_old.tmp # Step 2: actually delete $ find /tmp -name "*.tmp" -mtime +7 -type f -delete # Remove a directory tree (use with extreme caution) $ rm -rf /tmp/build_artifacts/
⚠️

Never rm -rf / or rm -rf $VAR/ if $VAR might be empty. Always quote variables: rm -rf "${DIR}/". Consider set -u at the top of scripts to error on unset variables.

07 Your app binary needs to be executable by the app user only, config files readable by group but not others, and a script needs SUID. How do you manage Linux permissions? chmod · chown ▾

Linux permissions: every file has owner/group/others with read(4), write(2), execute(1) bits. chmod changes permissions, chown changes owner.

bash
# App binary: rwx for owner, nothing for group/others $ chmod 700 /opt/myapp/server # Config: rw-r----- (owner rw, group r, others none) $ chmod 640 /opt/myapp/.env # Symbolic mode (easier to read) $ chmod u+x,g-w,o= script.sh # Change owner to app:appgroup recursively $ chown -R app:app /opt/myapp/ # Verify $ ls -la /opt/myapp/ -rwx------ app app server -rw-r----- app app .env
💡

Quick mnemonic: 7=rwx, 6=rw-, 5=r-x, 4=r--. The digits are owner/group/others. For secrets like .env or SSL keys: always 600 (only owner reads/writes).

08 Production logs are showing 500 errors. You need to find all lines containing "ERROR" in the last hour's logs, case-insensitively, and exclude health-check noise. How do you grep effectively? grep ▾

grep searches text using patterns (basic regex by default). It's one of the most-used commands in log analysis and incident response.

bash
# Case-insensitive search $ grep -i "error" app.log # Exclude health-check noise, show line numbers $ grep -in "error" app.log | grep -v "healthcheck" # Search recursively across all log files $ grep -r "OutOfMemory" /var/log/ # Show 3 lines before and after for context $ grep -C 3 "NullPointerException" app.log # Count occurrences $ grep -c "500" access.log 342 # Extended regex: match ERROR or WARN $ grep -E "ERROR|WARN" app.log
💡

Use grep -v to invert (exclude). Flags: -A N after, -B N before, -C N context. For binary logs, add -a to force text mode. grep -l returns only filenames with matches — great for scripting.

09 A security audit requires finding all SUID binaries on the system and all files modified in the last 24 hours under /etc. How do you use find for this? find ▾

find traverses the filesystem with rich filtering: by name, type, permissions, timestamps, size, owner, and more — all combinable with AND/OR logic.

bash
# Find all SUID binaries (security audit) $ find / -perm /4000 -type f 2>/dev/null /usr/bin/sudo /usr/bin/passwd /usr/bin/su # Files modified in /etc in last 24h $ find /etc -mtime -1 -type f # Find large files >100MB (disk cleanup) $ find /var -size +100M -type f -ls # Execute action: compress old logs $ find /var/log -name "*.log" -mtime +30 -exec gzip {} \;
💡

-mtime -1 means "modified less than 1 day ago". +1 means "more than 1 day ago". Always redirect stderr 2>/dev/null to suppress permission denied messages on system-wide finds.

10 In a deploy script, you need to print a colored status message and write a multi-line config snippet to a file without opening an editor. How do you use echo and heredocs? echo · heredoc ▾

echo prints text. Heredocs (<<EOF) write multi-line content inline in scripts — essential for generating configs on the fly.

bash
# Colored output in CI/CD scripts $ echo -e "\033[32m✔ Deploy successful\033[0m" ✔ Deploy successful # Write nginx config from a script (heredoc) $ cat > /etc/nginx/conf.d/app.conf <# Append without overwrite $ echo "APP_VERSION=1.2.3" >> .env
💡

Use <<'EOF' (quoted) to prevent variable expansion inside heredocs — useful when writing scripts that contain $variables meant for another context (like a Kubernetes manifest). <<-EOF strips leading tabs for clean indentation.

11 You're on a minimal cloud instance with no internet. How do you look up what a command does, find all flags for tar, and search for commands related to "network"? man · --help · apropos ▾

Linux has a built-in documentation system. Knowing how to navigate it means you're never truly without a reference, even in airgapped environments.

bash
# Full manual (navigate with / to search, q to quit) $ man tar # Quick flag summary $ tar --help | less # Search man pages by keyword $ apropos network ifconfig (8) - configure a network interface ip (8) - show/manipulate routing, devices netstat (8) - print network connections # Open specific section (e.g. system calls vs commands) $ man 2 open # section 2 = system calls $ man 5 crontab # section 5 = file formats
💡

Man page sections: 1=user commands, 2=syscalls, 3=library functions, 5=file formats, 8=sysadmin commands. tldr tar (if installed) gives practical examples — great complement to the full man page.

12 You want to watch live errors streaming in from an app log, and also grab just the last 50 lines of a rotated log file. How do you use head and tail for real-time monitoring? head · tail ▾

tail -f is the go-to for live log monitoring — it blocks and streams new lines as they appear. head shows the beginning of files.

bash
# Live log stream (Ctrl+C to stop) $ tail -f /var/log/nginx/error.log # Follow AND filter (show only 500 errors live) $ tail -f app.log | grep --line-buffered "ERROR" # Follow even if file is rotated (Docker logs) $ tail -F /var/log/app.log # capital F reopens if rotated # Last 50 lines of compressed log $ tail -n 50 app.log.1 # Show first 10 lines of all files in dir $ head /etc/nginx/conf.d/*.conf
💡

Use -F (capital) instead of -f when following logs managed by logrotate — -F reopens the file by name when it detects the inode changes, ensuring you keep watching even after rotation.

13 In a post-deploy sanity check, you need to count how many HTTP 500 errors occurred in today's access log, and how many unique IPs are in it. What's your one-liner? wc · cut · sort ▾

wc counts words/lines/bytes. Combine it with pipes to build quick log analytics without any external tools.

bash
# Count 500 errors $ grep " 500 " access.log | wc -l 47 # Unique IPs (field 1 in nginx access log) $ cut -d' ' -f1 access.log | sort -u | wc -l 1203 # Top 10 IPs by request count $ cut -d' ' -f1 access.log | sort | uniq -c | sort -rn | head -10 8921 203.0.113.42 3441 198.51.100.7 892 192.168.1.1
💡

This pattern — cut → sort → uniq -c → sort -rn → head — is a classic DevOps one-liner for finding top offenders (IPs, endpoints, error codes) in any structured log without needing ELK or Datadog.

14 You have a list of deployed microservice versions from two sources that might overlap. How do you combine them, remove duplicates, and sort by version number? sort · uniq · comm ▾

sort and uniq are typically used together: sort groups identical lines, then uniq collapses them. comm compares two sorted files.

bash
# Combine, deduplicate, sort $ cat source1.txt source2.txt | sort -u # Sort by version number (numeric, 2nd field) $ sort -t. -k1,1n -k2,2n -k3,3n versions.txt 1.2.0 1.10.1 2.0.0 # Lines only in source1 (set difference) $ comm -23 source1_sorted.txt source2_sorted.txt # Show duplicates only $ sort combined.txt | uniq -d
💡

sort -V (version sort) handles version strings naturally: 1.2.10 sorts after 1.2.9 correctly, which numeric sort gets wrong. Use it for any version-string comparison in release pipelines.

15 Explain stdin, stdout, stderr and how to redirect them. How do you capture both output and errors from a CI build command into separate files while also showing it on screen? pipes · redirect ▾

Every process has 3 file descriptors: stdin(0), stdout(1), stderr(2). Mastering redirection is foundational for CI scripts and log capture.

bash
# Separate stdout and stderr $ make build >build.log 2>build.err # Merge stderr into stdout $ npm run build >all.log 2>&1 # Show on screen AND save (tee) $ make build 2>&1 | tee build.log # Discard output (suppress noise) $ some_noisy_cmd > /dev/null 2>&1 # Process substitution (compare two command outputs) $ diff <(ls dir1/) <(ls dir2/)
💡

tee is essential in CI pipelines: it streams output to the terminal in real-time (so GitHub Actions shows live logs) while simultaneously writing to a file. Use tee -a to append.

Intermediate Processes, Services & Networking Q 16–30
16 Your app is consuming 100% CPU. How do you find all related processes, see their full command lines, and understand the process hierarchy (parent/child)? ps ▾

ps (process status) shows a snapshot of running processes. Unlike top, it's scriptable and works well in pipelines.

bash
# Show all processes, full format $ ps aux USER PID %CPU %MEM VSZ RSS STAT COMMAND app 1234 99.5 2.1 512M 85M R node /opt/app/server.js # Process tree (parent/child relationships) $ ps auxf root 1 0.0 systemd └─ app 1234 99.5 node server.js └─ app 1235 0.0 node worker.js # Find process by name $ ps aux | grep nginx # Custom output: PID, CPU, MEM, command $ ps -eo pid,pcpu,pmem,comm | sort -k2 -rn | head
💡

pstree -p gives a cleaner tree view. pgrep nginx returns just PIDs. pidof nginx also works. In containers, remember ps shows only the container's process namespace by default.

17 A runaway worker process is consuming all memory. How do you kill it gracefully first, then forcefully if it doesn't respond? What's the difference between signals? kill · signals ▾

Signals are asynchronous messages to processes. Different signals trigger different behaviors — choosing the right one matters for clean shutdowns.

bash
# Graceful shutdown (SIGTERM=15) — app can clean up $ kill -15 1234 # or: kill 1234 (default is TERM) # Force kill (SIGKILL=9) — cannot be caught or ignored $ kill -9 1234 # Kill by name (all matching processes) $ pkill -f "node server" # Reload config without restart (SIGHUP) $ kill -HUP $(cat /var/run/nginx.pid) # Common signals: SIGTERM (15) → graceful shutdown (default kill) SIGKILL (9) → immediate, unblockable SIGHUP (1) → reload config SIGINT (2) → like Ctrl+C SIGUSR1/2 → user-defined (nginx: reopen logs)
⚠️

Never jump straight to kill -9. It bypasses cleanup handlers — the process can't flush buffers, release locks, or save state. Always try SIGTERM first, wait 5–10 seconds, then escalate to SIGKILL.

18 Production instance is sluggish. How do you quickly identify which process is eating CPU/memory in real time, and what does load average actually mean? top · htop ▾

top is the classic interactive process monitor. htop (if available) adds colors, mouse support, and easier killing. Understanding load average is crucial for capacity decisions.

bash
$ top load average: 3.42, 2.91, 2.15 ← 1min, 5min, 15min Tasks: 142 total, 2 running %Cpu: 89.2 us, 4.1 sy, 0.0 ni, 6.3 id PID USER %CPU %MEM COMMAND 1234 app 88.1 3.2 node 892 root 2.1 0.4 containerd # Useful top keypresses: P → sort by CPU M → sort by memory k → kill selected PID 1 → show per-CPU breakdown q → quit # Non-interactive snapshot (for scripts) $ top -bn1 | head -20
💡

Load average = average number of processes wanting CPU. On a 4-core machine: load 4.0 = 100% utilized, load >4 = overloaded. Check nproc for core count. A load average lower than nproc with high CPU% per process usually means one thread is the bottleneck — not total saturation.

19 Disk alert fires at 95% full on a prod server. How do you find which filesystem is full, and then drill down to find the largest directories consuming space? df · du ▾

df shows filesystem-level disk usage. du shows directory/file sizes — together they're the standard disk firefighting toolkit.

bash
# Which filesystems are full? $ df -h Filesystem Size Used Avail Use% Mounted on /dev/xvda1 50G 48G 2.0G 96% / /dev/xvdb 20G 1.2G 19G 7% /data # Top 10 largest directories in /var $ du -sh /var/* | sort -rh | head -10 38G /var/log 4.5G /var/lib 800M /var/cache # Drill deeper into /var/log $ du -sh /var/log/* | sort -rh | head 35G /var/log/app.log ← found it!
⚠️

A disk can show 100% full but du doesn't add up — this often means a deleted file is still held open by a running process. Find it with lsof | grep deleted and restart the holding process to release the space.

20 Your CI pipeline needs to create a compressed archive of build artifacts, then on the deployment server extract only specific files from it without unpacking everything. How do you wield tar? tar ▾

tar (tape archive) bundles files. With compression flags it's the standard format for Linux build artifacts, backups, and container layer tarballs.

bash
# Create gzipped archive $ tar -czf artifacts-v1.2.tar.gz ./dist # c=create z=gzip f=filename # List contents without extracting $ tar -tzf artifacts-v1.2.tar.gz dist/index.html dist/assets/main.js dist/config/app.yaml # Extract only config files $ tar -xzf artifacts-v1.2.tar.gz dist/config/ # Extract to specific directory $ tar -xzf artifacts-v1.2.tar.gz -C /opt/deploy/ # Use bzip2 (smaller, slower) or xz (smallest) $ tar -cJf archive.tar.xz dist/ # J = xz
💡

Memory aid: czf = Create Zip File, xzf = eXtract Zip File, tzf = lisT Zip File. Always add v flag while debugging (verbose), drop it in CI scripts to reduce noise.

21 You need to SSH into a bastion host, then jump from there to a private instance that has no public IP. How do you configure SSH to do this transparently in one command? ssh · ProxyJump ▾

ssh with jump hosts and ~/.ssh/config aliases are essential for managing cloud infrastructure with private networking.

bash
# One-liner jump host $ ssh -J ubuntu@bastion.myco.com ubuntu@10.0.1.50 # ~/.ssh/config (the clean way) Host bastion HostName bastion.myco.com User ubuntu IdentityFile ~/.ssh/id_rsa Host private-app HostName 10.0.1.50 User ubuntu ProxyJump bastion IdentityFile ~/.ssh/id_rsa # Now just: $ ssh private-app # Copy file through bastion to private host $ scp -J bastion app.tar.gz ubuntu@10.0.1.50:/opt/
💡

Add ServerAliveInterval 60 and ServerAliveCountMax 3 to your SSH config to prevent long-running sessions (like deploys) from being dropped by NAT timeouts on cloud providers.

22 You need to check if an external API is reachable from a server, download a file with resume support, and post JSON to a webhook — all from the terminal. When do you use curl vs wget? curl · wget ▾

curl is a full HTTP client (headers, methods, auth, streaming). wget is focused on downloading files with retry/resume. Both are essential DevOps tools.

bash
# Check API health + show status code $ curl -o /dev/null -s -w "%{http_code}\n" https://api.myapp.com/health 200 # POST JSON to webhook $ curl -X POST -H "Content-Type: application/json" \ -d '{"event":"deploy","version":"1.2.3"}' \ https://hooks.slack.com/services/xxx # Download with resume (wget) $ wget -c https://releases.hashicorp.com/terraform/1.7.0/tf.zip # Follow redirects, fail on HTTP errors $ curl -fsSL https://get.docker.com | bash
💡

curl -fsSL flags: -f fail on error (non-2xx), -s silent (no progress), -S show errors, -L follow redirects. This combo is the safe standard for piping install scripts. Use curl -I URL to fetch headers only (fast health check).

23 After deploying your app as a systemd service, it crashes on startup. How do you check its status, view logs, enable auto-start on boot, and reload the config without a restart? systemctl ▾

systemctl is the control interface for systemd — the init system on all modern Linux distros. It manages service lifecycle, dependencies, and boot targets.

bash
# Check status with recent logs $ systemctl status myapp ● myapp.service - My Application Loaded: loaded (/etc/systemd/system/myapp.service; enabled) Active: failed (Result: exit-code) since ... Process: 1234 ExecStart=/opt/myapp/server (code=exited, status=1) Jun 19 10:00:01 server myapp[1234]: Error: cannot bind to port 80 # Enable on boot + start now $ systemctl enable --now myapp # Reload unit file after editing $ systemctl daemon-reload $ systemctl restart myapp # Reload app config (if supported via SIGHUP) $ systemctl reload nginx # List all failed services $ systemctl --failed
💡

After editing a .service file, you must run systemctl daemon-reload before the changes take effect — systemd caches unit files in memory. Skipping this is a common source of confusion.

24 A service crashed at 3am. How do you view its logs from that specific time window, filter by severity, and export them to a file for a post-mortem report? journalctl ▾

journalctl queries the systemd journal — a structured, indexed log store that survives logrotate and supports time-based, unit-based, and priority filtering.

bash
# Logs for a specific time window $ journalctl -u myapp --since "2024-06-19 03:00:00" --until "2024-06-19 03:30:00" # Only errors and above (emerg,alert,crit,err) $ journalctl -u myapp -p err # Follow live (like tail -f) $ journalctl -u myapp -f # Export as plain text for post-mortem $ journalctl -u myapp --since "2024-06-19 03:00" --no-pager > postmortem-logs.txt # How much disk journal is using $ journalctl --disk-usage Archived and active journals take up 2.3G
💡

Priority levels: 0=emerg, 1=alert, 2=crit, 3=err, 4=warning, 5=notice, 6=info, 7=debug. Use -p 0..3 to see everything critical and above. Set SystemMaxUse=500M in /etc/systemd/journald.conf to cap disk usage.

25 Your app reads database credentials from environment variables. How do you set them for the current session, persist them, and pass them into a process without exposing them in ps aux? env · export ▾

Environment variables are the standard way to configure applications in containerized and 12-factor architectures. Handling them securely matters.

bash
# Set and export to child processes $ export DB_PASSWORD="s3cr3t" $ export DB_HOST="db.internal" # Pass inline without polluting shell env $ DB_PASSWORD="s3cr3t" node server.js # Load from .env file $ set -a; source .env; set +a # OR with env prefix tool: $ env $(cat .env | xargs) node server.js # View all current env vars $ env | sort $ printenv DB_HOST
⚠️

Environment variables show up in /proc/PID/environ — readable by root. Never pass secrets as command-line arguments (they appear in ps aux to all users). Use env vars, files with restricted permissions, or secret managers (Vault, AWS SSM).

26 You need to schedule a database backup script to run at 2:30am every Sunday, and a log rotation job every 15 minutes on weekdays. How do you set up cron correctly? cron · crontab ▾

cron is the time-based job scheduler. crontab manages per-user schedules. Understanding the 5-field syntax and gotchas prevents midnight surprises.

bash
$ crontab -e # edit current user's crontab # Format: MIN HOUR DAY MONTH WEEKDAY command # ┌───── minute (0-59) # │ ┌─── hour (0-23) # │ │ ┌─ day of month (1-31) # │ │ │ ┌ month (1-12) # │ │ │ │ ┌ weekday (0=Sun) # │ │ │ │ │ 30 2 * * 0 /opt/scripts/db-backup.sh >> /var/log/backup.log 2>&1 */15 * * * 1-5 /opt/scripts/rotate-logs.sh # View current crontab $ crontab -l # List another user's crontab $ crontab -u app -l
⚠️

Cron runs in a minimal environment — PATH doesn't include /usr/local/bin. Always use full paths in cron scripts (/usr/bin/python3 not python3). Always redirect stdout and stderr to a log file, or cron will email you on every run (or silently fail).

27 A config file has the old database host hardcoded in 200 places. How do you replace all occurrences in-place with sed? How do you also delete all comment lines starting with #? sed ▾

sed (stream editor) processes text line-by-line with substitution, deletion, and insertion commands. It's the go-to for scripted config file manipulation.

bash
# Replace all occurrences in-place (-i) $ sed -i 's/old-db.internal/new-db.internal/g' config.yaml # Backup original before editing (safe practice) $ sed -i.bak 's/localhost/10.0.1.5/g' app.conf # Creates config.conf.bak automatically # Delete comment lines and blank lines $ sed -i '/^#/d; /^$/d' config.ini # Replace only on lines containing "database" $ sed -i '/database/s/5432/5433/' config.yaml # Preview changes without modifying (dry-run) $ sed 's/old/new/g' config.yaml | diff config.yaml -
💡

Always do a dry-run first (omit -i). Use -i.bak in production to auto-create backups. For multi-file replacements: find . -name "*.yaml" -exec sed -i 's/old/new/g' {} \;

28 You have a space-delimited access log and need to sum the total bytes transferred, compute the average response time, and print a report of the top 5 endpoints. How do you use awk? awk ▾

awk is a full text-processing language. It splits each line into fields and lets you perform calculations, aggregations, and conditional logic.

50 An on-call alert fires: "load average 45 on a 4-core machine." Walk through the complete incident response process to diagnose whether it's CPU-bound, I/O-bound, a runaway process, or a fork bomb. uptime · vmstat · iostat · dmesg ▾

High load average is a symptom, not a cause. The diagnosis is a structured elimination process — this is the workflow that separates experienced SREs from beginners.

bash
